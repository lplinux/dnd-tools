# ⚔️ D&D Campaign Tools

A self-hosted Node.js + React web application for tabletop RPG campaign management.

## Architecture overview

```
dnd-tools/
├── app.js            ← Express server, all REST API routes, PostgreSQL schema
├── public/           ← Express static: Vite build output (app/) + shared assets + fallback index.html
├── frontend/         ← React 19 + Vite SPA (the entire UI)
│   └── src/
│       ├── api/      ← Typed fetch wrappers (one module per API group)
│       ├── contexts/ ← Theme, Auth, Toast, Confirm
│       ├── hooks/    ← useAuth, useTheme, useToast, useAsync, …
│       ├── components/layout/  ← AppHeader, AppLayout
│       ├── components/ui/      ← Button, Modal, Badge, Select, Spinner, FormField, InfoCard, ModalField
│       ├── components/map/     ← Reusable map renderer (MapStage, viewport, geometry)
│       └── pages/    ← All modules (React-owned)
├── docs/             ← Per-module README.md files (served via GET /api/docs/:slug)
└── scripts/          ← DB setup and admin creation
```

The React SPA is the entire UI; it talks to the Express REST API and is served
by Express's catch-all route (with `/api/*` reserved for the API).

## Quick start — local development

**Requirements:** Node.js 18+, PostgreSQL 14+.

### 1. Backend (Express)

```bash
# Install backend dependencies
npm install

# Configure environment
cp .env.example .env
# Edit .env — set the DB_* variables, SESSION_SECRET and ID_SECRET
```

`.env` example:
```env
DB_HOST=localhost
DB_PORT=5432
DB_USER=dndtools
DB_PASSWORD=yourpassword
DB_NAME=dndtools
SESSION_SECRET=change-me-to-something-long-and-random
PORT=3080
ID_SECRET=change-me-too
```

```bash
# Start Express (auto-initialises DB schema on first run)
node app.js
# → http://localhost:3080
```

### 2. React frontend (dev server)

```bash
cd frontend
npm install
npm run dev
# → http://localhost:5173  (proxies /api/* to Express on :3080)
```

> **Run both servers simultaneously** — Express on `:3080` for the API,
> Vite on `:5173` for the React dev server. The Vite proxy handles all
> `/api/*` requests transparently.

## Production build

```bash
cd frontend
npm run build
# Outputs to public/app/

# Then serve everything from Express:
node app.js   # serves public/app/index.html as the SPA entry point
```

> The SPA catch-all route is already wired in `app.js` (it serves
> `public/app/index.html` for any non-API path), so a built frontend is served
> automatically.

## Running with Docker

```bash
docker build -t dnd-tools .

docker run -d \
  --name dnd-tools \
  -p 3080:3080 \
  -e DB_HOST=host -e DB_PORT=5432 \
  -e DB_USER=dndtools -e DB_PASSWORD=yourpassword -e DB_NAME=dndtools \
  -e SESSION_SECRET=your-secret-here \
  -e ID_SECRET=your-id-secret-here \
  dnd-tools
```

With PDFs mounted:
```bash
docker run -d \
  --name dnd-tools \
  -p 3080:3080 \
  -e DB_HOST=host -e DB_PORT=5432 \
  -e DB_USER=dndtools -e DB_PASSWORD=yourpassword -e DB_NAME=dndtools \
  -e SESSION_SECRET=your-secret-here \
  -v /absolute/path/to/your/pdfs:/app/pdfs:ro \
  dnd-tools
```

## Environment variables

| Variable | Required | Default | Description |
|---|---|---|---|
| `DB_HOST` | Yes | — | PostgreSQL host |
| `DB_PORT` | Yes | — | PostgreSQL port |
| `DB_USER` | Yes | — | PostgreSQL user |
| `DB_PASSWORD` | Yes | — | PostgreSQL password |
| `DB_NAME` | Yes | — | Database name |
| `SESSION_SECRET` | Yes | — | Secret for session cookie signing |
| `ID_SECRET` | No | `dnd-id-secret-change-me` | HMAC secret behind public share tokens — **change it**, or your links match every default deployment |
| `PORT` | No | `3080` | HTTP listen port |

> `DATABASE_URL` is **not** read by `app.js`. Only `scripts/setup-db.js` and
> `scripts/create-admin.js` understand it, so setting it on its own points the
> scripts and the server at different databases. Use the `DB_*` variables.

## Rules data attribution

The NPC / PC sheet offers ⓘ lookups for conditions, damage types and spells against the
**2024 System Reference Document (SRD 5.2)**, fetched at runtime from
[dnd5eapi.co](https://www.dnd5eapi.co).

> SRD 5.2 © Wizards of the Coast LLC, licensed under
> [CC-BY-4.0](https://creativecommons.org/licenses/by/4.0/).

No rules text is stored by this app — lookups are fetched on demand and cached only for the
browser session. The SRD is a **subset** of the 2024 Player's Handbook, so an entry can be
absent from the lookup while still existing in the book; the sheet says so rather than claiming
the element does not exist. Lookups degrade to plain text when offline.
