# ⚔️ D&D Campaign Tools

A self-hosted Node.js + React web application for tabletop RPG campaign management.

## Architecture overview

```
dnd-tools/
├── app.js            ← Express server, all REST API routes, PostgreSQL schema
├── public/app/       ← Express static: Vite build output (gitignored; `npm run build` creates it)
├── frontend/         ← React 19 + Vite SPA (the entire UI)
│   └── src/
│       ├── api/      ← Typed fetch wrappers (one module per API group)
│       ├── contexts/ ← Theme, Auth, Toast, Confirm
│       ├── hooks/    ← useAuth, useTheme, useToast, useAsync, …
│       ├── components/layout/  ← AppHeader, AppLayout
│       ├── components/ui/      ← Button, Modal, Badge, Select, Spinner, FormField, InfoCard, ModalField
│       ├── components/map/     ← Reusable map renderer (MapStage, viewport, geometry)
│       └── pages/    ← All modules (React-owned)
├── docs/             ← Per-module README.md files (served via GET /api/docs/:slug)
└── scripts/          ← DB setup and admin creation
```

The React SPA is the entire UI; it talks to the Express REST API and is served
by Express's catch-all route (with `/api/*` reserved for the API).

## Quick start — local development

**Requirements:** Node.js **20+** — `.nvmrc` pins **24**, so `nvm install` in this directory
gets you the right one, and the container image runs Node 24 LTS. PostgreSQL is supplied by
`run.sh` in a container; you only need your own if you skip Docker.

> Node 18 reached end-of-life in April 2025 and Node 20 in April 2026. `run.sh` refuses anything
> below 20 and tells you how to upgrade.

### The one-command option

`run.sh` does the whole bootstrap — checks prerequisites, creates `.env` from the example,
installs both dependency trees, **runs the test suite**, builds the frontend, then brings up
PostgreSQL and the app in containers and waits for each to be healthy:

```bash
bash run.sh          # Ctrl+C stops everything cleanly
SKIP_TESTS=1 bash run.sh   # bypass the test gate
```

It needs Docker (or Podman) with Compose. A failing test stops the run before anything is built
or started. The manual steps below are the same thing by hand, without containers.

> **A fresh clone is missing `public/`, `pdfs/`, `.env` and `node_modules/` — that is correct.**
> All four are gitignored: `public/app/` is Vite build output (`npm run build` creates it),
> `pdfs/` is your own rulebooks, `.env` is copied from `.env.example` on first run, and
> `node_modules/` comes from `npm install`. `run.sh` creates or restores every one of them.
> Deleting `public/` is always safe; deleting `pdfs/` loses whatever you put there.

### 1. Backend (Express)

```bash
# Install backend dependencies
npm install

# Configure environment
cp .env.example .env
# Edit .env — set the DB_* variables, SESSION_SECRET and ID_SECRET
```

`.env` example:
```env
DB_HOST=localhost
DB_PORT=15432          # compose publishes postgres on 15432, not 5432
DB_USER=dndtools
DB_PASSWORD=yourpassword
DB_NAME=dndtools
SESSION_SECRET=change-me-to-something-long-and-random
PORT=3080
ID_SECRET=change-me-too
```

```bash
# Start Express (auto-initialises DB schema on first run)
node app.js
# → http://localhost:3080
```

### 2. React frontend (dev server)

```bash
cd frontend
npm install
npm run dev
# → http://localhost:5173  (proxies /api/* to Express on :3080)
```

> **Run both servers simultaneously** — Express on `:3080` for the API,
> Vite on `:5173` for the React dev server. The Vite proxy handles all
> `/api/*` requests transparently.

## Code quality — tests and linting

Both run from the repo root and cover both halves of the codebase.

```bash
npm test          # Vitest — the pure domain modules (calendar, 5e rules,
                  #   road-network distances, SRD/Open5e payload flattening)
npm run lint      # ESLint 9, flat config, CommonJS backend + ESM/JSX frontend
npm run lint:fix  # the same, with autofixable problems corrected
```

In `frontend/` there is also `npm run test:watch` for a watching Vitest.

The suite is `environment: 'node'` over pure modules only — there is no DOM and no backend
harness, so it runs in about a second. `run.sh` gates the bootstrap on it (step 5 of 15).

`react-hooks/rules-of-hooks` is an **error**: it catches conditional-hook bugs, which have
crashed a page here before. `exhaustive-deps` is a warning, because changing a dependency array
needs judgement rather than a reflex fix.

## Running with Docker

```bash
docker build -t dnd-tools .

docker run -d \
  --name dnd-tools \
  -p 3080:3080 \
  -e DB_HOST=host.docker.internal -e DB_PORT=5432 \
  -e DB_USER=dndtools -e DB_PASSWORD=yourpassword -e DB_NAME=dndtools \
  -e SESSION_SECRET=your-secret-here \
  -e ID_SECRET=your-id-secret-here \
```

## Environment variables

| Variable | Required | Default | Description |
|---|---|---|---|
| `DB_HOST` | Yes | — | PostgreSQL host |
| `DB_PORT` | Yes | — | PostgreSQL port |
| `DB_USER` | Yes | — | PostgreSQL user |
| `DB_PASSWORD` | Yes | — | PostgreSQL password |
| `DB_NAME` | Yes | — | Database name |
| `SESSION_SECRET` | Yes | — | Secret for session cookie signing |
| `ID_SECRET` | No | `dnd-id-secret-change-me` | HMAC secret behind public share tokens — **change it**, or your links match every default deployment |
| `PORT` | No | `3080` | HTTP listen port |

> `DATABASE_URL` is **not** read by `app.js`. Only `scripts/setup-db.js` and
> `scripts/create-admin.js` understand it, so setting it on its own points the
> scripts and the server at different databases. Use the `DB_*` variables.

## User roles

| Role | Access |
|---|---|
| `admin` | All DM tools + user management |
| `dm` | Campaigns, journey maps, timelines, PDF viewer, PC sheets (all players) |
| `player` | Own PC sheet, timeline view |

First run: **nothing to do** — `run.sh` creates an initial `admin` account with a random
password and prints it once at the end (also written to `/tmp/dndtools-init-creds.txt`, mode
0600, and deleted after it is shown). Use `node scripts/create-admin.js` to add *another* admin
later, or to recover if you lost that password.

## Rules data attribution

The NPC / PC sheet offers ⓘ lookups for conditions, damage types and spells against the
**2024 System Reference Document (SRD 5.2)**, fetched at runtime from
[dnd5eapi.co](https://www.dnd5eapi.co).

> SRD 5.2 © Wizards of the Coast LLC, licensed under
> [CC-BY-4.0](https://creativecommons.org/licenses/by/4.0/).

No rules text is stored by this app — lookups are fetched on demand and cached only for the
browser session. The SRD is a **subset** of the 2024 Player's Handbook, so an entry can be
absent from the lookup while still existing in the book; the sheet says so rather than claiming
the element does not exist. Lookups degrade to plain text when offline.
